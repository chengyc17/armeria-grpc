## 修复：example-server 启动后立刻退出（exit 0，无报错）

**症状**：Spring 上下文启动成功（Started ... 2.637s），但 Armeria 服务端从未启动（无 "Armeria server started" 日志），随后 Nacos 线程池销毁、进程 exit 0。

**根因（深入反编译确认）**：Spring Boot 3.2.0 的 `OnBeanCondition.Spec` 构造器里，`@ConditionalOnBean(annotation = X.class)` 用在 @Bean 方法上时，**只检查了 type/value 和 name 是否为空，没有检查 annotation**——只要两者为空就会从方法返回类型推导出 `types` 集合（如 Server、GovernanceConfigManager）。`isAllMatched()` 要求 annotations/names/types 全部无未匹配项 → 推导出的返回类型自引用永远不匹配 → 条件 FAIL → armeriaServer/governanceConfigManager bean 根本不创建 → 非 Web 应用（无 spring-web）JVM 没有非守护线程保持存活 → 进程干净退出（exit 0）。

**验证过程**：`--debug` 条件评估报告显示 `@ConditionalOnBean (types: com.linecorp.armeria.server.Server)` 未匹配（而非 annotations: GrpcService）→ 铁证。用 `-verbose:class` 确认类加载顺序、反编译 OnBeanCondition/MatchResult 确认 isAllMatched 语义。

**修复**：`RpcAutoConfiguration` 两处 `@ConditionalOnBean(annotation = GrpcService.class)` 改为 `@ConditionalOnBean(BindableService.class)`（@GrpcService 实现本身就是 BindableService，类型匹配可靠；源码加注释说明原因）。

**验证**：条件报告 matched（found bean 'orderServiceImpl'）；18099 端口完整启动：Armeria server started → Registered service 100004337 -> ip:18099 (weight=1.0, metadata={idc=bj}) → Governance config applied（soa.json 未配置，全关闭）→ 进程保持运行。

**经验**：Spring Boot 3.2 的 @ConditionalOnBean(annotation=) 在 @Bean 方法上不可靠（返回类型推导成额外必匹配条件）；跨 bean 用类型匹配更稳。诊断"启动即退出"先查条件评估报告（--debug），再查是否因无存活线程。
