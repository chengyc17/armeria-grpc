## 项目代码通读

通读了 armeria-grpc 项目全部 8 个模块的源码，梳理了整体架构。

### 项目定位
基于 Armeria + gRPC + Nacos + Spring Boot 3 的微服务 RPC 框架，类似内部 SOA 基础设施。

### 8 个模块概览
- **armeria-grpc-common**: 基础包。`@GrpcService` 注解、`AppIdReader`(从 proto option app_id field 1001 解析)、`GrpcServices`(单服务约束)、`OpsEnvironmentPostProcessor`(从 C:\ops\env.properties 注入 env 变量作为 Nacos namespace)
- **armeria-grpc-config**: Nacos 配置中心客户端自动配置。`AppConfigService` 按 dataId 拉取/订阅配置(默认 soa.json)，支持 YAML/JSON/Properties/AUTO 格式，变更发布 `AppConfigChangedEvent`
- **armeria-server**: 核心 gRPC 基础设施 starter。`RpcAutoConfiguration` 自动启动 Armeria server、注册 Nacos、注入客户端 stub(按 AbstractStub 字段类型识别，无 @GrpcClient 注解)、客户端上下文透传、服务治理(黑白名单→限流→熔断三层)、JSON Schema 自描述端点
- **armeria-grpc-gateway**: 非阻塞 HTTP 网关(端口 9082)。Armeria 原生 HTTP Server，`POST /{appId}/api/{method}` 从 Nacos 发现实例并流式转发，五重保障缓存(缓存+订阅+负缓存+定时刷新+stale-while-error)
- **armeria-grpc-canary**: gRPC 接口测试控制台(端口 9081)。Spring Boot Web 应用，Web UI 查询 Nacos 实例、拉取 /rpc/schema 枚举接口、在线发起 unframed HTTP/JSON 调用
- **armeria-grpc-api**: Proto 制品发布服务(端口 9080)。接收 .proto 上传，内嵌 Maven(MavenCli.doMain) 生成 gRPC stub jar 并 deploy 到 Nexus
- **example-server**: 示例服务提供方。`OrderServiceImpl`(@GrpcService) 内存版订单服务，appId=100004337，端口 18081
- **example-client**: 示例服务消费方。纯客户端模式(rpc.server.enabled=false)，stub 自动注入，REST 接口触发 gRPC 调用

### 关键设计
- appId 作为一等公民：proto ServiceOptions 扩展 field 1001，贯穿服务注册/发现/路由/治理/配置
- 每进程单服务约束：GrpcServices.requireSingle() 强制一个实例只暴露一个 @GrpcService
- 客户端注入无注解：GrpcClientBeanPostProcessor 按 AbstractStub 字段类型反射注入，Nacos 实例变更自动重建
- 配置三级兜底：soa.json 应用段 > global 段 > 本地 rpc.governance.* 属性

## namespace/group 兜底逻辑澄清（Q&A）

用户询问兜底逻辑是否在 common、能否放 Armeria 容器。核实结论：
- 值的来源在 common（OpsEnvironmentPostProcessor 注入 env、AppIdReader 解析 appId），但兜底决策复制在 4 个模块（config/server/gateway/canary 各自的装配类）——DRY 违反，建议收敛到 common 的 NacosClientEnvironment 工具类
- 路径事实：代码 Windows 硬编码 C:/ops（本机实际生效此路径，env=fat），Linux 才是 user.home；用户以为是统一用户目录
- 概念澄清：namespace/group 是进程级启动时定死的值，不适合放 Armeria RequestContext（请求作用域）；Armeria 容器只适用于 ClientContextHolder 那种请求级上下文（InheritableThreadLocal 替换目标是它）

## ClientContextHolder 重构：InheritableThreadLocal → Armeria RequestContext

### 关键技术点（Armeria 1.27）
- ContextHook 在 1.27 不存在（1.28+ 才有），正确做法是 RequestContext attribute
- `com.linecorp.armeria.common.AttributeKey` 不存在，必须用 `io.netty.util.AttributeKey.valueOf(name)`（需 netty-common 在 classpath）
- 上下文在事件循环线程和 `blockingTaskExecutor()` 自动可见；自有线程池需 `ctx.makeContextAware(...)`
