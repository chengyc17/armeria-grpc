# 注册中心与配置中心抽象层方案

> 目标：业务代码（server / gateway / 业务应用）**只依赖抽象层**，注册中心可切换 Nacos / Eureka / K8s Service，配置中心可切换 Nacos / Apollo；切换 = 换依赖 + 改配置 + 重启，业务零改动。

---

## 1. 现状与问题

| 链路 | 现状 | 问题 |
|---|---|---|
| 注册/发现 | `NacosInstanceRegistrar`（server）直连 `NamingService`；网关 `NacosInstanceRegistry` / `NacosEndpointGroup` 直连 Nacos | 强依赖 nacos-client，无法换 Eureka / K8s |
| 配置中心 | `AppConfigService`（旧 armeria-grpc-config 模块，已拆分）直连 Nacos `ConfigService` | 强依赖 Nacos，无法换 Apollo |

## 2. 抽象层设计（两个独立 SPI，均零业务依赖）

### 2.1 注册中心 SPI（`armeria-grpc-registry-api`，零第三方依赖）

```java
/** 统一实例模型（nacos instance / eureka instance / k8s endpoint 统一映射） */
public record RegistryInstance(
        String ip, int port, double weight,
        boolean healthy, boolean enabled,
        Map<String, String> metadata) {
    public String address() { return ip + ":" + port; }
}

/** 注册侧（服务端用）：只负责注册/注销 */
public interface ServiceRegistrar extends AutoCloseable {
    String name();                       // 配置里的 name，如 nacos-main
    String type();                       // 配置里的 type，如 nacos / eureka / k8s
    void register(String serviceName, String ip, int port, double weight,
                  Map<String, String> metadata) throws Exception;
    void deregister(String serviceName, String ip, int port);
    default void close() {}              // 释放连接；幂等
}

/** 发现侧（客户端/网关用）：查询 + 订阅变更 */
public interface ServiceDiscovery extends AutoCloseable {
    String name();
    String type();
    List<RegistryInstance> lookup(String serviceName);
    void subscribe(String serviceName, Listener listener);
    void unsubscribe(String serviceName, Listener listener);
    default void close() {}
    @FunctionalInterface
    interface Listener { void onInstancesChanged(List<RegistryInstance> instances); }
}

/** 全角色接口：具体实现（Nacos/Eureka/K8s）都实现它，上层按角色依赖 */
public interface Registry extends ServiceRegistrar, ServiceDiscovery {}

/** 工厂：type -> 创建实例；Spring 容器收集所有工厂 bean */
public interface RegistryFactory {
    String type();
    Registry create(RegistryProperties.Item props) throws Exception;
}

/** 配置模型（registry-api，中立字段） */
public record RegistryProperties(
        boolean failFast, List<Item> registries) {
    public record Item(
            String name, String type, String serverAddr,
            String namespace, String group, double weight,
            boolean registerEnabled, Map<String, String> options) {}
}
```

**角色隔离**：服务端只注入 `List<ServiceRegistrar>`（拿不到 lookup/subscribe）；客户端/网关只注入 `List<ServiceDiscovery>`。K8s 是纯发现源，`register()` 实现为 no-op + WARN。

### 2.2 配置中心 SPI（`armeria-grpc-config-api`，仅带 jackson + snakeyaml 解析）

```java
/** 配置源：统一按 dataId 拉取/订阅/解析；变更时发 Spring 事件，不暴露订阅 API */
public interface ConfigSource extends AutoCloseable {
    String type();                              // nacos / apollo
    String getRawConfig(String dataId);         // 原始内容
    boolean isLoaded(String dataId);
    boolean isLoaded();                         // 任意一个 dataId 已加载
    Map<String, Object> getConfig(String dataId);   // 结构化（YAML 嵌套 Map / JSON / properties 扁平）
    Map<String, String> getProperties(String dataId); // 扁平 key=value
    Map<String, String> getProperties();        // 所有 dataId 合并扁平视图
    String getProperty(String dataId, String key, String defaultValue);
    default void close() {}
}
```

- **dataId 是统一标识**：Nacos 里就是 dataId；Apollo 里映射为 namespace 名。
- **解析器（yaml/json/properties/auto）放 config-api**，所有实现复用同一套 `ConfigParser`。
- **变更通知**：各实现内部订阅 → 解析 → 发 `AppConfigChangedEvent(dataId, oldRaw, newRaw)`，治理等上层只监听事件（与现状一致，不破坏现有消费方）。

## 3. 模块结构

按域分组，抽象层实现统一收在 `armeria-grpc-config/` 与 `armeria-grpc-registry/` 两个子目录下（Maven 依赖按 artifactId 解析，目录只影响可读性）：

```
根目录/
├── armeria-grpc-config/                配置中心分组
│   ├── armeria-grpc-config-api         配置 SPI + 解析器（零第三方依赖）
│   ├── armeria-grpc-config-nacos       Nacos 实现（改造自旧 armeria-grpc-config）
│   └── armeria-grpc-config-apollo      Apollo 实现（JDK HttpClient 自研客户端）
├── armeria-grpc-registry/              注册中心分组
│   ├── armeria-grpc-registry-api       注册/发现 SPI（零依赖）
│   ├── armeria-grpc-registry-nacos     Nacos 实现（唯一持 nacos-client）
│   ├── armeria-grpc-registry-eureka    Eureka 实现（JDK HttpClient 自研客户端）
│   └── armeria-grpc-registry-k8s       K8s Service 实现（极简：Service DNS 直连，无轮询/无 API 调用）
├── armeria-grpc-common                 公共：appId 解析、多中心合并端点组
├── armeria-server / armeria-grpc-api / canary / gateway / example-*   业务模块
```

> 注：分组目录下不设中间聚合 pom，各模块 parent 仍指向根 `pom.xml`（relativePath `../../pom.xml`），根 pom 直接列带分组前缀的 `<module>` 路径；分组是纯目录组织，不改任何依赖坐标。

**依赖方向**：`armeria-server` / `armeria-grpc-gateway` 编译期只依赖两个 `-api` 模块；实现模块通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` + `@ConditionalOnClass` 挂载工厂/配置源 bean。切换注册中心 = 换 pom 依赖 + 改 `type` + 重启。

## 4. 注册中心实现

### 4.1 Nacos（registry-nacos）
现有 `NamingService` 逻辑整体迁移：注册走 `registerInstance`，发现走 `selectInstances` + `subscribe`；`RegistryInstance` 转换边界（weight/metadata/healthy 映射）。

### 4.2 Eureka（registry-eureka）
`eureka-client` 标准客户端：
- 注册：`ApplicationInfoManager` + `EurekaClient.register()`，metadata 走 `InstanceInfo` 的 `MetadataMap`；
- 发现：`EurekaClient.getApplications()` 按 appId（大写）过滤 + `getInstancesByVipAddress`；订阅用 `EurekaEventListener`（注册表变更即刷新）；
- 注销：`EurekaClient.shutdown()` 自动注销。
- 注意点：Eureka appId 大写约定（serviceName 转大写做匹配）；`server-addr` 配 eureka server URL（如 `http://127.0.0.1:8761/eureka`）。

### 4.3 K8s Service（registry-k8s）—— 只发现、不注册（Service DNS 直连，极简）

不查 SRV 记录、不调 K8s REST API：目标地址直接就是 **Service 的集群内域名**
`<appId>.<namespace>.svc.cluster.local`（多副本由 Service ClusterIP 内部负载均衡，调用方不感知 Pod IP）。

- **service 名 = appId**：`lookup(serviceName)` 的入参就是注册时的 serviceName（客户端由 stub 反推 appId），不再做任何解析；
- **namespace = ops env.properties 的 `env` 值**：由工厂读 Spring property `env`（armeria-grpc-common 的 `OpsEnvironmentPostProcessor` 注入）；也可在 `registries[]` 显式配 `namespace` 覆盖；
- **端口**：`options.port` 必填（Service 端口，如 18081）；`options.cluster-domain` 可选，默认 `svc.cluster.local`；
- **零后台线程**：域名恒定，`subscribe` 只登记 listener 并立即推送一次当前快照，无轮询无推送；
- **实例元数据**：无 idc，发现侧按 `idc` 就近逻辑自动退化为全部可用（与现状一致）；
- **注册侧**：`register()` no-op + WARN（K8s 的 endpoint 由 Deployment/Service 自动维护）；`type: k8s` 只配在发现侧（网关/客户端）。

## 5. 配置中心实现

### 5.1 Nacos（config-nacos，改造自旧 armeria-grpc-config）
现有 `AppConfigService` 逻辑（data-ids 拉取 + 订阅 + 重试 + 解析）原样保留，改为实现 `ConfigSource`：持有 `ConfigService`，`dataId → snapshot` 映射不变，变更仍发 `AppConfigChangedEvent`。

### 5.2 Apollo（config-apollo）
`apollo-client` 标准客户端：
- **dataId → namespace 映射**：`data-ids: [application, soa]` → Apollo `ConfigService.getConfig("application")` / `getConfig("soa")`（Apollo 默认 namespace 名可带 `.properties/.yaml/.json` 后缀，交给统一 `ConfigParser` 按后缀解析）；
- 拉取：`config.getPropertyNames()` + `getProperty(k, null)` 组装扁平 Map，再按 `format`/后缀解析；
- 订阅：`config.addChangeListener(ChangeListener)` → 变更时重读该 dataId → 发 `AppConfigChangedEvent`；
- 客户端需要 `apollo.meta`（meta server 地址）+ 应用 `app.id`（读取 META-INF/app.config 已有 appId，或 `rpc.config.app-id` 覆盖）。

## 6. 配置示例

```yaml
# 服务端（example-server）：注册到多个中心
rpc:
  registry:
    fail-fast: false
    registries:
      - name: nacos-main
        type: nacos
        server-addr: 127.0.0.1:8848
      - name: eureka-backup
        type: eureka
        server-addr: http://127.0.0.1:8761/eureka
  config:
    type: nacos
    server-addr: 127.0.0.1:8848
    data-ids: [soa.json]
    format: auto
```

```yaml
# 网关（armeria-grpc-gateway）：发现侧，可混配 nacos + k8s
gateway:
  registries:
    - name: nacos-main
      type: nacos
      server-addr: 127.0.0.1:8848
    - name: k8s-prod
      type: k8s
      # namespace 不配时默认取 ops env.properties 的 env 值（本示例配 prod 覆盖）
      namespace: prod
      options:
        port: 18081        # 必填：Service 端口
        # cluster-domain: svc.cluster.local   # 可选，默认 svc.cluster.local
```

```yaml
# 配置中心切 Apollo
rpc:
  config:
    type: apollo
    meta-server: http://127.0.0.1:8080
    # app-id 默认读 META-INF/app.config 的 appid
    data-ids: [application, soa]
```

## 7. 兼容与迁移

1. **旧配置不破坏**：`rpc.nacos.server-addr`（注册）与 `rpc.config.server-addr`（配置）仍可用——注册侧合成单条 nacos registry，配置侧默认 `type=nacos`；
2. **服务名约定不变**：appId 即注册 serviceName；配置中心 dataId 语义不变；
3. **治理/网关消费方零改动**：`AppConfigChangedEvent` 与 `GovernanceConfigManager`、`GatewayService` 的接口不变；
4. **依赖变化**：nacos-client 从 server/gateway pom 移除，改由 `registry-nacos` / `config-nacos` 传递提供。

## 8. 验证计划

| 项 | 方式 |
|---|---|
| SPI 解耦复核 | 编译期检查 server/gateway 无 `com.alibaba.nacos` / `com.netflix` / apollo 引用（只允许在实现模块） |
| Nacos 端到端 | 本机 Nacos 3.2.3：注册 → 发现 → 调用 → 注销（现有链路回归） |
| 多中心合并 | nacos + eureka 同时配，网关发现侧按 ip:port 去重合并 |
| Eureka | 本地 eureka-server 模拟 + `InMemory` 测试替身单测 |
| K8s | 单测：`lookup` 返回 `<appId>.<ns>.svc.cluster.local:port`、namespace 默认取 env、port 缺失报错 |
| Apollo | apollo-client 单测（mock `ConfigService`）+ 变更事件单测 |
| 配置切换 | 同一应用 `rpc.config.type` 在 nacos/apollo 间切换，治理配置一致生效 |
